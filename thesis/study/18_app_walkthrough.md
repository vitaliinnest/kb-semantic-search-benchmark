## 1. Загальна навігація

Топ-меню (доступне на всіх сторінках):

```
[KB Search] Пошук | Документи | Файли | Індекси | Benchmark | Вибір моделі
                                                                Домен: [▼]
```

### Перемикач доменів

Правий верхній кут. Можеш переключатися між:
- **Техніка / IT** (tech)
- **Юридична база** (legal)
- **Медицина** (medical)

Перемикач **зберігає** контекст — якщо ти на сторінці пошуку, переключив домен, ти залишаєшся на сторінці пошуку але вже в новому домені.

### URL-параметр `domain`

Усі сторінки приймають `?domain=tech|legal|medical`. Якщо не вказати — `tech` (за замовчуванням).

## 2. `/` — Пошук (головна)

### Що показує

```
┌─────────────────────────────────────────────────────────────┐
│ 🔍 [_______________________________________________] Шукати │
│                                                              │
│ Модель: ⚫ BGE-M3 (0.6722) ⚫ Qwen3 (0.6325) ⚫ ... ⚫ BM25  │
│                                                              │
│ Top-K: 5 ↑↓                                                  │
│                                                              │
│ Швидкі запити: 🔵 churn prediction  🔵 ...                  │
└─────────────────────────────────────────────────────────────┘

Результати:
┌─────────────────────────────────────────────────────────────┐
│ #1 score=0.654  doc_id: 2025_M_IUS_Potapenko_AO.pdf         │
│ ...сніпет тексту чанку (400 символів)...                    │
│ [Розгорнути повний текст] [Завантажити документ]            │
├─────────────────────────────────────────────────────────────┤
│ #2 ...                                                       │
└─────────────────────────────────────────────────────────────┘
```

### Ключові елементи

#### Поле пошуку
Вводиш запит → натискаєш «Шукати» → результати оновлюються.

#### Плашки моделей
Список моделей, **відсортований за nDCG@10** з останнього бенчмарку. Найкраща — перша. Підсвічена — поточна. Клік перемикає модель.

Біля кожної моделі — її nDCG@10 у дужках (наприклад «BGE-M3 (0.6722)»). Це підказує, **наскільки якісна** модель.

#### Top-K
Скільки результатів показати. Дефолт 5.

#### Switch домену
Працює як на інших сторінках.

#### Швидкі запити (chips)
Готові приклади для click-and-try. Підтягуються з benchmark/queries.jsonl.

### Що означає score

- Для embedding моделей — **cosine similarity** (0-1). Чим вище, тим релевантніше.
- Для BM25 — **сирий BM25 score** (від ~5 до ~50). Чим вище, тим релевантніше.

**Шкали різні** — не порівнюй embedding score з BM25 score напряму.

### Як цим користуватись для демо

Запит: `прогноз відтоку клієнтів (churn prediction)`
- Спробуй з BGE-M3 → отримай релевантні фрагменти з Potapenko
- Перемкни на BM25 → побачиш гірші фрагменти (абстракт, бібліографія)

Це наочна демонстрація переваги семантичного над лексичним.

## 3. `/documents`

### Що показує

Перегляд **всіх чанків** у corpus, згрупованих за **джерелом** (документом).

```
Документи (tech):  10 джерел, 770 чанків

┌─────────────────────────────────────────────────────────────┐
│ 📄 2025_M_IUS_Potapenko_AO.pdf  (84 чанків)        [▼]      │
├─────────────────────────────────────────────────────────────┤
│   Чанк 1 (1234 символи): ...текст...                        │
│   Чанк 2 (987 символи): ...текст...                         │
│   ...                                                        │
├─────────────────────────────────────────────────────────────┤
│ 📄 fastText.pdf  (52 чанків)                       [▼]      │
└─────────────────────────────────────────────────────────────┘
```

### Що ти бачиш

1. **Скільки документів** у домені — 10 для tech
2. **Скільки чанків** загалом — 770
3. **Кожен документ** — у згорнутому вигляді, з кількістю чанків
4. Можна **розгорнути** і подивитись усі чанки

### Як використовувати

- Перевірити, що дані завантажилися правильно
- Подивитись, як виглядають чанки після чанкінгу
- Зрозуміти, **що** шукає система

### У демо

Можна швидко показати: «ось мій корпус — 10 документів про програмну інженерію, ML, etc. Усього 770 чанків після чанкінгу».

## 4. `/raw`

### Що показує

Файли для **завантаження** і налаштування чанкінгу.

```
Файли (tech):  10 файлів

┌─────────────────────────────────────────────────────────────┐
│ Upload файлів:                                              │
│ [Виберіть файли...] [Завантажити]                           │
│                                                              │
│ Запустити чанкінг:                                          │
│ min_words: 300   max_words: 800   overlap: 80              │
│ [Запустити]                                                 │
└─────────────────────────────────────────────────────────────┘

Список:
┌─────────────────────────────────────────────────────────────┐
│ 📄 fastText.pdf      2.1 MB    25.11.2025 12:34   [Видалити] │
│ 📄 2025_M_IUS_...    8.7 MB    01.12.2025 09:00   [Видалити] │
│ ...                                                          │
└─────────────────────────────────────────────────────────────┘
```

### Як використовувати

1. Upload документів (PDF, DOCX, TXT, MD)
2. Налаштувати параметри чанкінгу
3. Натиснути «Запустити чанкінг»
4. Чекати на завершення (статус оновлюється)

### Підтримувані формати

- `.pdf` — через `pdfminer` або `pypdf`
- `.docx` — через `python-docx`
- `.txt` — пряме читання
- `.md` — пряме читання

### У демо

Зазвичай **не показуємо** — це internal infra. Скоріше скажемо: «ось куди завантажуються файли».

## 5. `/build`

### Що показує

Сторінка побудови **FAISS-індексів** для кожної моделі.

```
Побудова індексів (tech):  4 чанки, 770 чанків

┌─────────────────────────────────────────────────────────────┐
│ ☑ BM25 (Okapi)                  [Запустити]                 │
│   Статус: ✓ Побудовано 25.11.2025                          │
│   Файли: bm25.pkl (45 KB), meta.jsonl                      │
├─────────────────────────────────────────────────────────────┤
│ ☑ BGE-M3 (BAAI/bge-m3)          [Запустити]                 │
│   Статус: ✓ Побудовано 25.11.2025                          │
│   Файли: faiss.index (3.1 MB), meta.jsonl, model.json      │
│   Параметри: max_seq=256, batch=32                         │
├─────────────────────────────────────────────────────────────┤
│ ☐ E5-base                       [Запустити]                 │
│ ☐ Qwen3-Embedding               [Запустити]                 │
│ ☐ nomic-embed                   [Запустити]                 │
└─────────────────────────────────────────────────────────────┘
```

### Як використовувати

1. Вибрати моделі (галочки)
2. Налаштувати параметри (за необхідності)
3. Натиснути «Запустити»
4. Чекати — побудова Background job
5. Слідкувати за статусом (оновлюється через polling)

### Час побудови

Для tech corpus (~770 чанків):
- BM25: < 1 секунди
- E5-base: ~30 секунд
- BGE-M3: ~1-2 хвилини
- Qwen3: ~5-10 хвилин (CPU!)
- nomic: ~1 хвилина

### У демо

**Не показуємо** — це time-consuming. Скоріше скажемо: «індекси вже побудовані для всіх моделей».

### Ключові елементи

#### Рекомендована модель
Зверху великим — переможець MCDA. Підсвічена як «Парето-оптимальна» якщо вона у Парето-множині.

#### Парето-множина
Плашки моделей, які пройшли Парето-фільтр. На tech: BGE-M3, E5-base, BM25. nomic і Qwen3 — поза множиною (домінуються).

#### Профілі ваг
Готові набори:
- **Технічний** — баланс
- **Юридичний** — пріоритет MRR
- **Медичний** — пріоритет Recall
- **За замовчуванням** — балансовий

Клікаєш — слайдери оновлюються.

#### Слайдери
Кожен критерій — окремий слайдер. Можна тонко настроїти. Після зміни (debounce 450мс) — таблиця **перерахується**.

**Якщо змінити вручну** — профіль автоматично стає «Користувацький».

#### Таблиця
- **SCORE** — інтегральна оцінка U(a)
- **Pareto** — чи в Парето-множині
- **Сирі / Нормалізовані** перемикач — показати справжні значення метрик або нормалізовані (для розуміння як працює нормалізація)

### Як використовувати в демо

**Section 3 і 4** демо-відео:
1. Покажи дефолтну рекомендацію — BGE-M3
2. Тягни слайдер Latency до 0.50
3. Покажи, як рекомендація змінюється на E5-base
4. Це **wow moment** — показує цінність MCDA

### Кольорова градація SCORE

- Зелений — найвищий
- Жовто-помаранчевий — середній
- Червоний/малиновий — низький

## 8. `/benchmark/explorer`

### Що показує

Список **всіх 100 запитів** у benchmark з per-query метриками.

```
🔍 Benchmark Explorer (Техніка / IT)              100 запитів

Сортування: [За ID] [Кращий nDCG] [Гірший] [Розрив] [Середнє]
Фільтр: [Всі] [Ідеальні] [Промахи] [Великий розрив] [З моделлю: ▼]

Лідер по моделях:  BGE-M3: 45  Qwen3: 28  E5-base: 15  BM25: 8  nomic: 4

┌────────────────────────────────────────────────────────────┐
│ q1: «що таке Random Forest»                                │
│ Лідер: BGE-M3 (1.0)  Розрив: 0.65  Серед: 0.72             │
├────────────────────────────────────────────────────────────┤
│ q2: «принцип роботи нейромережі»                           │
│ Лідер: Qwen3 (0.95)  Розрив: 0.30  Серед: 0.81             │
├────────────────────────────────────────────────────────────┤
│ ...                                                         │
└────────────────────────────────────────────────────────────┘
```

### Що ти бачиш

- **100 запитів** з останнього benchmark
- Для кожного — який модель **лідер**, який розрив у nDCG між найкращою і найгіршою
- Лічильник: скільки запитів кожна модель «виграє»

### Як використовувати

- Знайти **складні запити** (всі моделі поганий nDCG)
- Знайти **ідеальні запити** (всі моделі справились)
- **Зрозуміти**, де якась модель домінує

### Фільтри

- **Ідеальні** — запити, де хоча б одна модель досягла nDCG ≥ 0.999
- **Промахи** — запити, де всі моделі мають nDCG < 0.001
- **Великий розрив** — різниця > 0.3 між найкращою і найгіршою

### У демо

**Не основний фокус**, але можна швидко показати «ось 100 запитів, в кожному моделі ранжуються по-різному».

## Перевірочні питання

### Q1. Які сторінки в застосунку?

**A:** 8 основних:
- `/` — пошук
- `/documents` — корпус
- `/raw` — upload
- `/build` — індекси
- `/benchmark` — метрики
- `/benchmark/selection` — MCDA
- `/benchmark/explorer` — per-query
- `/benchmark/explorer/<qid>` — деталі запиту

### Q2. Що показує `/benchmark/selection`?

**A:** MCDA wizard. Згори — рекомендована модель з її score (наприклад BGE-M3, 0.9040). Парето-множина — список Парето-оптимальних моделей. Слайдери ваг критеріїв з 4 готовими профілями. Таблиця всіх моделей з SCORE, який перераховується в реальному часі при зміні ваг.

### Q3. Чому plashки моделей на `/` відсортовані саме так?

**A:** За **спадаючим nDCG@10** з останнього benchmark. Перша — найкраща. Біля кожної моделі — її nDCG у дужках. Це підказує користувачу, **яка модель найкраща** до вибору.

### Q4. Що означає підсвітка чанка в `/benchmark/explorer/<qid>`?

**A:** Підсвічуються чанки, які експерти позначили як **релевантні** в qrels. Зазвичай зелена смужка зліва і ⭐ біля номеру. Це дозволяє візуально побачити, **знайшла** модель релевантний чанк чи ні, і на якій позиції.

### Q5. Як працює перемикач домену?

**A:** URL-параметр `domain=tech|legal|medical`. Кожна сторінка приймає його. При зміні — сторінка оновлюється з даними нового домена. Якщо ти на `/`, переключиш домен — залишишся на `/`, але вже з новим індексом.

### Q6. Якщо bench-маrk не запускався — що буде на `/benchmark`?

**A:** Сторінка покаже повідомлення «Бенчмарк ще не запускався» і кнопку «Запустити benchmark». Якщо запустиш — почнеться background-job, статус оновлюється в реальному часі.

### Q7. Як швидко знайти конкретний запит у explorer?

**A:** Кілька шляхів:
1. **Сортування** — за ID, кращим nDCG, розривом, тощо
2. **Фільтри** — «ідеальні», «промахи», «велике розходження»
3. **Фільтр по моделі** — «де лідер X»
4. **Прямий URL** — `/benchmark/explorer/q6?domain=tech`

### Q8. Чи можу я запустити benchmark тільки для однієї моделі?

**A:** Через UI — ні (запускаються всі моделі домена). Через CLI — так:
```bash
python src/evaluate_benchmark.py \
    --queries .../queries.jsonl \
    --qrels .../qrels.jsonl \
    --model-artifacts artifacts/tech/bge-m3 \
    --top-k 10 --output results/...
```

### Q9. Як показати «той самий запит з різними моделями» у демо?

**A:** На `/` вводиш запит. Отримуєш результати з поточною моделлю. Перемикаєш плашку моделі — **сторінка перевантажується**, але запит зберігається в URL → той самий запит з новою моделлю. Робиш такий перемикач у демо — наочно показує різницю.

### Q10. Що показати, коли комісія питає «де у вас MCDA»?

**A:** Натиснути на сторінку `/benchmark/selection`. Показати:
- Рекомендована модель (BGE-M3) із score
- Парето-множина
- Слайдери ваг — пояснити що це
- Профілі — пояснити, що для кожного домена своя логіка
- Тягнути слайдер → показувати як рекомендація змінюється в реальному часі

Це **інтерактивний MCDA wizard** — найунікальніша частина роботи.

# 03. Косинусна схожість, L2-нормалізація, dot product

> **TL;DR:** Косинусна схожість міряє «кут між векторами», ігноруючи їхню довжину. Формула: `cos(a,b) = (a·b) / (||a|| × ||b||)`. Якщо вектори **L2-нормалізовані** (поділені на довжину), формула спрощується до `cos(a,b) = a·b` — простого dot product. Цим трюком користується FAISS IndexFlatIP у твоїй роботі: економить обчислення поділу при пошуку.

## 1. Інтуїція: чому кут, а не відстань

Уяви два вектори — це **стрілки** з початку координат.

```
       y
       |
       |       a
       |      /
       |    /
       |  /
       |/_____________________> x
       |\
       |  \
       |    \
       |      b
       |
```

«Наскільки схожі» a і b? Є два варіанти:
1. **Відстань між кінчиками стрілок** (евклідова відстань)
2. **Кут між стрілками** (косинусна схожість)

### Чому для текстів — кут

Тексти різної **довжини** дають вектори різної **довжини**. Документ з 1000 слів матиме «довший» вектор за документ з 50 слів — навіть якщо обидва говорять про одне.

Якщо міряти **відстань** — короткий і довгий документ на одну тему будуть **далеко** один від одного.

Якщо міряти **кут** — вони **в одному напрямку** (про одне), і кут між ними малий → cos ≈ 1.

**Кут ігнорує довжину**, дивиться лише на «куди вказує» вектор. Це **саме те**, що треба для семантичної схожості.

## 2. Геометрія векторів у 2D

Спрощено, на двох вимірах.

```
       y
       |       
   1.0 |       a = (3, 4) ←─── вектор довжиною 5
       |      /
       |    /
       |  /
   0.5 |/
       |
       0 ──────────────────────────> x
       |  0.5  1.0  1.5  2.0  2.5  3.0
```

- Вектор `a = (3, 4)`. Довжина: `√(3² + 4²) = √25 = 5`.
- Вектор `b = (6, 8)`. Довжина: `√(36 + 64) = √100 = 10`.

Обидва вказують **в одному напрямку** (з початку координат угору-вправо). Кут між ними — **0°**.

cos(0°) = **1.0** → ідеальна схожість.

А вектор `c = (-4, 3)`?
- Довжина: `√(16 + 9) = √25 = 5`.
- Дивиться угору-вліво. Кут з `a` — **90°**.
- cos(90°) = **0** → ніяк не пов'язані.

Вектор `d = (-3, -4)`?
- Довжина: 5.
- Дивиться вниз-вліво. Кут з `a` — **180°** (повна протилежність).
- cos(180°) = **-1** → антипод.

## 3. Формула косинусної схожості

### Канонічна формула

```
                a · b
cos(a, b) = ─────────────
            ||a|| · ||b||
```

де:
- `a · b` — **dot product** (скалярний добуток): `a₁·b₁ + a₂·b₂ + ... + aₙ·bₙ`
- `||a||` — **L2-норма** вектора a: `√(a₁² + a₂² + ... + aₙ²)`
- `||b||` — те саме для b

### Властивості

- `cos(a, b) ∈ [-1, +1]` для будь-яких a, b
- **+1**: вектори в одному напрямку (ідентичний сенс)
- **0**: перпендикулярні (нема зв'язку)
- **-1**: протилежні (антоніми)

### Чому "косинус"

Бо це справді **косинус кута** між векторами. Із тригонометрії:

```
a · b = ||a|| · ||b|| · cos(θ)
```

Перевпорядкувавши:

```
cos(θ) = (a · b) / (||a|| · ||b||)
```

### Cosine **distance** vs cosine **similarity**

Деякі бібліотеки використовують поняття **cosine distance**:
```
cos_distance = 1 - cos_similarity
```

Це **відстань** (0 = ідентичні, 2 = протилежні). FAISS використовує **similarity** через IndexFlatIP. Не плутай.

## 4. L2-норма: що це таке

### Визначення

L2-норма вектора `v = (v₁, v₂, ..., vₙ)`:

```
||v|| = √(v₁² + v₂² + ... + vₙ²)
```

Це **довжина** вектора в евклідовому просторі.

### Альтернативи

| Назва | Формула | Інтерпретація |
|---|---|---|
| L1 (Манхеттенська) | `|v₁| + |v₂| + ... + |vₙ|` | Сума абсолютних значень |
| L2 (евклідова) | `√(Σvᵢ²)` | Звичайна довжина |
| L∞ (Чебишева) | `max(|vᵢ|)` | Максимальний компонент |

У ML здебільшого використовують L2.

### Властивості L2-норми

- `||v|| ≥ 0` завжди
- `||v|| = 0` ⟺ `v` — нульовий вектор
- `||c·v|| = |c| · ||v||` — масштабування
- `||a + b|| ≤ ||a|| + ||b||` — трикутна нерівність

### L2-нормалізація

«Нормалізувати» вектор — поділити його на свою довжину:

```
v_normalized = v / ||v||
```

Результат — **одиничний вектор** (довжина = 1), що вказує в тому ж напрямку, що й оригінал.

```
v = (3, 4),    ||v|| = 5
v_norm = (3/5, 4/5) = (0.6, 0.8)
||v_norm|| = √(0.36 + 0.64) = √1 = 1   ✓
```

## 5. Магічний трюк

Якщо обидва вектори L2-нормалізовані (`||a|| = ||b|| = 1`), формула косинусу спрощується:

```
                a · b
cos(a, b) = ───────────── = (a · b) / 1 = a · b
            ||a|| · ||b||
```

Тобто **простий dot product**.

### Чому це круто

**Dot product дуже швидкий** (просто сума множень). А обчислення `||a||` для кожного вектора — це додатковий `sqrt(sum_of_squares)`, який треба **на кожний пошук**.

Якщо нормалізувати **один раз під час індексації** і **один раз під час кодування запиту**, то всі мільйони порівнянь при пошуку — це **тільки dot products**. Економія: 5-10x швидше.

### FAISS IndexFlatIP

Саме на цьому ґрунтується. IP = Inner Product = dot product. Він **не обчислює** косинус — він просто рахує dot product. Але якщо твої вектори нормалізовані заздалегідь, **результат dot product = cosine similarity**.

Тому **обов'язково** треба:
1. Нормалізувати вектори чанків ПЕРЕД додаванням в індекс
2. Нормалізувати запит ПЕРЕД виклику `index.search(query, k)`

У твоєму коді (`src/embedding_models.py`) це робиться через `vectors / np.linalg.norm(vectors, axis=1, keepdims=True)`.

## 6. Альтернативні метрики

### Евклідова відстань (L2 distance)

```
d(a, b) = ||a - b|| = √(Σ(aᵢ - bᵢ)²)
```

**Інтерпретація:** пряма відстань між кінчиками стрілок.

**Коли використовувати:** якщо довжина вектора важлива (наприклад, embeddings зображень з предтренованих CNN).

**Чому не для текстів:** довжина вектора корелює з довжиною тексту, що не семантично значуще.

### Manhattan distance (L1)

```
d(a, b) = Σ|aᵢ - bᵢ|
```

**Інтерпретація:** «розстань як їде таксі по сітці вулиць».

**Коли:** робастна до викидів. Зрідка для текстів.

### Inner product

```
ip(a, b) = a · b
```

Як ми обговорили, для нормалізованих векторів — це cosine similarity. Для ненормалізованих — пропорційне до cos і довжин.

### Dot product vs IP — одне і те ж

Так. «Inner product» = «scalar product» = «dot product». Різні назви, одна операція.

## 7. Числовий приклад

Конкретно з числами. Уяви два вектори в 4-вимірному просторі (для прикладу — реальні embeddings 768-1024 dim):

```
a = (1, 2, 3, 4)
b = (2, 4, 6, 8)
```

### Крок 1: довжини

```
||a|| = √(1² + 2² + 3² + 4²) = √(1+4+9+16) = √30 ≈ 5.477
||b|| = √(2² + 4² + 6² + 8²) = √(4+16+36+64) = √120 ≈ 10.954
```

### Крок 2: dot product

```
a · b = 1·2 + 2·4 + 3·6 + 4·8 = 2 + 8 + 18 + 32 = 60
```

### Крок 3: cosine

```
cos(a,b) = 60 / (5.477 × 10.954) ≈ 60 / 60.0 = 1.0
```

Бо `b = 2 · a` — той самий напрямок, довший вдвічі. Cosine = 1 — максимальна схожість.

### Крок 4: нормалізуємо

```
a_norm = a / 5.477 = (0.183, 0.365, 0.548, 0.730)
b_norm = b / 10.954 = (0.183, 0.365, 0.548, 0.730)  ← однакові!
```

### Крок 5: dot product нормалізованих

```
a_norm · b_norm = 0.183² + 0.365² + 0.548² + 0.730²
              = 0.0335 + 0.1332 + 0.3003 + 0.5329
              ≈ 1.0  ✓
```

Те саме значення, без поділу.

### Інший приклад: перпендикулярні

```
a = (1, 0)
b = (0, 1)

a · b = 1·0 + 0·1 = 0
||a|| = 1, ||b|| = 1
cos = 0 / 1 = 0  ← нема схожості
```

### Протилежні

```
a = (1, 0)
b = (-1, 0)

a · b = -1
||a|| = 1, ||b|| = 1
cos = -1  ← антипод
```

## 8. Що буде, якщо забути нормалізацію

### Сценарій: ти кладеш ненормалізовані вектори в IndexFlatIP

```python
index = faiss.IndexFlatIP(768)
index.add(vectors)   # ← БЕЗ normalize_L2 спочатку

query_vec = model.encode_queries([query])  # ← теж не нормалізовано
scores, indices = index.search(query_vec, k=10)
```

Що піде не так:
1. FAISS поверне топ-K по **dot product** (бо це його суть)
2. Dot product = `||a|| · ||b|| · cos(θ)` — залежить від довжин
3. **Довгі** вектори будуть мати **більший dot product** просто через свою довжину, навіть якщо cos такий самий
4. Топ-K скривиться у бік **довших чанків** — переважно з більшою кількістю слів
5. Результат: пошук **упереджений у бік довгих документів**, не справді найрелевантніших

### Як перевірити

Якщо вектори нормалізовані:
- Усі scores ∈ [-1, 1]
- Перший результат завжди має score близький до 1.0 (якщо релевантний у корпусі)

Якщо НЕ нормалізовані:
- Scores можуть бути 50, 100, 200 — будь-які додатні (або від'ємні) числа
- Порядок результатів може бути спотворений

### У твоєму коді

Перевір метод `encode_queries()` та `encode_passages()` у `src/embedding_models.py`. Має бути щось на кшталт:

```python
vectors = vectors / np.linalg.norm(vectors, axis=1, keepdims=True)
```

після того як модель видала їх. Це **критично важливо** для коректного пошуку.

## 9. Як це реалізовано у FAISS і твоєму коді

### FAISS API

```python
import faiss
import numpy as np

# 1. Створюємо індекс
dim = 768
index = faiss.IndexFlatIP(dim)

# 2. Готуємо вектори (вже нормалізовані!)
vectors = ... # shape (N, dim)
faiss.normalize_L2(vectors)  # in-place нормалізація

# 3. Додаємо до індексу
index.add(vectors)

# 4. Пошук
query = ... # shape (1, dim)
faiss.normalize_L2(query)
scores, indices = index.search(query, k=10)

# scores ∈ [-1, 1], indices — позиції в індексі
```

### У твоєму репо

- `src/build_index.py` — десь так:
  ```python
  vectors = model.encode_passages(chunks)
  # модель сама нормалізує всередині
  index = faiss.IndexFlatIP(dim)
  index.add(vectors)
  faiss.write_index(index, str(artifacts_dir / "faiss.index"))
  ```

- `src/app.py:do_search()`:
  ```python
  query_vector = model.encode_queries([query])
  scores, indices = index.search(query_vector, top_k)
  ```

- `src/embedding_models.py:E5EmbeddingModel.encode_queries()`:
  ```python
  vectors = self.model.encode([f"query: {q}" for q in queries], ...)
  return vectors / np.linalg.norm(vectors, axis=1, keepdims=True)
  ```

(Конкретні рядки можуть відрізнятись, але логіка така.)

## 10. Перевірочні питання з відповідями

### Q1. Чому косинусну схожість, а не евклідову відстань для текстів?

**A:** Бо довжина вектора корелює з довжиною тексту, а не з сенсом. Косинус ігнорує довжину, дивиться лише на напрямок — це краще для семантики. Документ на 50 слів і документ на 1000 слів на одну тему мають **близькі cosines**, але **далеку евклідову відстань**.

### Q2. Що відбувається з вектором при L2-нормалізації?

**A:** Він ділиться на свою довжину. Результат — вектор тієї ж напрямленості, але довжиною рівно 1 (одиничний вектор). Це **проєкція на одиничну сферу** в багатовимірному просторі.

### Q3. Чому L2-нормалізація + dot product = cosine?

**A:** За визначенням, `cos(a,b) = (a·b) / (||a||·||b||)`. Якщо обидва вектори нормалізовані, `||a|| = ||b|| = 1`, тому знаменник дорівнює 1, і формула спрощується до `cos(a,b) = a·b`. Це **математична тотожність**, не апроксимація.

### Q4. У чому **обчислювальна вигода** цього трюку?

**A:** Dot product — це проста сума множень: `O(d)` операцій для вектора розмірності d. Обчислення `||a||` додає `sqrt(sum_of_squares)` — теж `O(d)`, але з повільнішим `sqrt`. При мільйоні порівнянь економія значна. Крім того, нормалізація **одноразова** — ми робимо її раз під час індексації, а не кожен раз під час пошуку.

### Q5. Що означає cosine = -1?

**A:** Вектори в протилежних напрямках — антоніми (у геометричному сенсі). У практиці для текстів значення зазвичай у діапазоні [0, 1] (рідко негативні), бо embedding-моделі тренуються давати позитивні «схожі» вектори.

### Q6. Може cosine бути більшим за 1?

**A:** Ні, ніколи. Математично `cos(θ) ∈ [-1, +1]`. Якщо FAISS повертає score 1.05 — вектори **не нормалізовані**, і ти отримуєш dot product, а не cosine. Перевір нормалізацію.

### Q7. Як перевірити, що твій embedding нормалізований?

**A:** Обчисли його L2-норму:
```python
import numpy as np
norm = np.linalg.norm(vector)
print(norm)  # має бути ≈ 1.0 (з точністю до 1e-6)
```

### Q8. Чому в FAISS — IndexFlatIP, а не IndexFlatL2?

**A:** IndexFlatIP — inner product. Для нормалізованих векторів дає cosine similarity. IndexFlatL2 — евклідова відстань, не підходить для семантичної схожості текстів (як обговорили в Q1). У твоїй роботі — `IndexFlatIP` саме тому.

### Q9. Що буде, якщо обчислити cosine для двох однакових векторів?

**A:**
```
cos(a, a) = (a·a) / (||a||·||a||) = ||a||² / ||a||² = 1
```
Завжди 1. Це наслідок того, що вектор сам із собою має кут 0° (паралельний сам собі).

### Q10. Чи може cosine similarity бути 0 між семантично подібними текстами?

**A:** Теоретично — так, якщо embedding-модель погано тренована або тексти **дуже різні за тематикою**. На практиці у сучасних моделях навіть тематично не пов'язані тексти мають cosine ≈ 0.1-0.3 (через спільні «загальні» виміри). Cosine 0 — рідкісне явище. Поріг релевантності зазвичай вище — близько 0.4-0.5.

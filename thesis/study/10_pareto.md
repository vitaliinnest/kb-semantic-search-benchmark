# 10. Парето-домінування

> **TL;DR:** Парето-домінування — спосіб **відсіяти явно гірші** альтернативи з кількох критеріїв. Альтернатива A **домінує** B, якщо A не гірша за всіма критеріями і краща хоча б за одним. Альтернативи, які не домінуються жодною — складають **Парето-фронт**. На tech-домені твоєї роботи Парето = {BGE-M3, E5-base, BM25}.

## 1. Інтуїція

### Приклад з машинами

Ти обираєш автомобіль за двома критеріями: **швидкість** і **економність**. Маєш 5 опцій:

| Авто | Швидкість (км/год) | Економність (л/100км) |
|---|---|---|
| A | 250 | 12 (багато жере) |
| B | 200 | 6 |
| C | 180 | 4 (дуже економно) |
| D | 220 | 8 |
| E | 100 | 9 |

Яке найкраще? Залежить.

- **A** — найшвидше, але прожере паливо.
- **C** — найекономніше, але повільне.
- **E** — і повільне (100), і не дуже економне (9).

Чи є серед них **явно гірші**?

Порівняй E з іншими:
- E vs B: 100 < 200 (E повільніше) AND 9 > 6 (E менш економне). **B виграє в обох**.
- Отже, **B домінує E**.

Хто розумний обере E, якщо B краще і там, і там? **Ніхто**. Можна **викинути** E з розгляду.

A, B, C, D — кожне домінує когось чи має своє «переваги»? Подивимось:
- A vs B: A швидше (250 > 200), B економніше (6 < 12). **Trade-off**. Жодне не домінує.
- A vs C: A швидше (250 > 180), C економніше (4 < 12). **Trade-off**.
- A vs D: A швидше (250 > 220), A менш економне (12 > 8). **Trade-off**.
- B vs C: B швидше (200 > 180), B менш економне (6 > 4). **Trade-off**.
- B vs D: B повільніше (200 < 220), B економніше (6 < 8). **Trade-off**.
- C vs D: C повільніше (180 < 220), C економніше (4 < 8). **Trade-off**.

**A, B, C, D — нікого не домінують**. Це **Парето-оптимальні** альтернативи. Жодну не можна викинути без розмови про **пріоритети**.

### Вибір з Парето-фронту

Який саме обрати — залежить від тебе:
- Швидкість важливіша → **A**
- Економність → **C**
- Баланс → **B** або **D**

Для **точного** вибору одного — потрібен ще **крок**: задати ваги (MCDA).

Парето — це лише **відсів** явно гірших. **Не сам вибір**.

## 2. Формальне визначення

### Векторне порівняння

Альтернатива a — вектор значень критеріїв: `a = (a_1, a_2, ..., a_k)`.

Альтернатива a **домінує** альтернативу b (записують `a ≻ b`), якщо:

1. `a_j ≥ b_j` для **всіх** критеріїв j (не гірша)
2. `a_j > b_j` для **хоча б одного** j (краща хоча б за одним)

(Це для критеріїв, які треба максимізувати. Для критеріїв на мінімізацію — нерівності переворачуються.)

### Парето-множина (фронт)

```
P = {a ∈ A | ∄ b ∈ A : b ≻ a}
```

Тобто множина альтернатив, **які ніхто не домінує**.

### Властивості

- **Унікальність:** Парето-множина однозначно визначається для даної задачі
- **Розмір:** від 1 (одна альтернатива домінує всіх) до |A| (ніхто нікого не домінує — рідко)
- **Транзитивність:** якщо A ≻ B і B ≻ C, то A ≻ C

## 3. Геометрія в 2D

Якщо у тебе 2 критерії — Парето-фронт можна побачити на графіку.

```
       якість
         ↑
      1.0│      ●A             ●Парето-оптимальні
         │
      0.8│       ●B            ●E (домінується B)
         │
      0.6│           ●C
         │
      0.4│              ●D
         │
       0 └────────────────────→ швидкість (мс/запит)
         0   100  200  300  400

A, B, C, D — Парето-фронт (з'єднують криву)
E — домінується B (B і швидше, і якісніше)
```

### Парето-фронт як крива

Зазвичай малюють як **угнуту криву** (для max-критеріїв), яка обмежує область знизу-зліва. Все, що **лежить нижче** — домінується (є щось краще і там, і там).

### Trade-off

Рух уздовж кривої = **обмін одного критерію на інший**. Не можна покращити обидва одночасно — Парето-фронт це **межа можливого**.

## 4. Чому це лише перший крок

Парето сам по собі **не дає** одну рекомендацію. Дає **множину раціональних опцій**.

### Сценарії

Якщо Парето-множина = {A, B, C}:
- Сценарій 1: користувачу важлива швидкість → A
- Сценарій 2: користувачу важлива якість → C
- Сценарій 3: баланс → B

Без **додаткової інформації про пріоритети** — Парето мовчить.

### MCDA довершує

MCDA (лінійна адитивна згортка) бере Парето-множину і **зважує** її ваговими коефіцієнтами:

```
U(a) = Σⱼ wⱼ · yⱼ(a)
```

Найвищий U — переможець. Це і є **остаточна рекомендація**.

Деталі MCDA — у наступному файлі ([11_mcda.md](11_mcda.md)).

### Чому два кроки

Можна було б одразу зробити лінійну згортку без Парето. Але:
- **Парето першим** — швидко відсіює явно гірші → менше обчислень для згортки
- **Інтерпретовність** — користувач бачить «ось 3 розумні опції», а не 10 моделей з якимись числами
- **Робастність** — якщо користувач незадоволений вагами, він **виключений з Парето-множини** не буде, а от перемога згортки може помінятися

## 6. Як обчислюється у коді

### `src/multi_criteria.py` (приблизно)

```python
def pareto_front(alternatives, criteria_directions):
    """
    alternatives: list of dicts {model_name: ..., metrics: [...]}
    criteria_directions: list of "max" or "min" per criterion
    Returns: list of Pareto-optimal model names
    """
    pareto = []
    for i, a in enumerate(alternatives):
        is_dominated = False
        for j, b in enumerate(alternatives):
            if i == j:
                continue
            if dominates(b, a, criteria_directions):
                is_dominated = True
                break
        if not is_dominated:
            pareto.append(a["model_name"])
    return pareto


def dominates(b, a, directions):
    """Returns True if b dominates a."""
    at_least_one_better = False
    for j in range(len(b["metrics"])):
        b_val = b["metrics"][j]
        a_val = a["metrics"][j]
        direction = directions[j]
        if direction == "max":
            if b_val < a_val:
                return False   # b гірша за хоч одним
            if b_val > a_val:
                at_least_one_better = True
        else:  # min
            if b_val > a_val:
                return False
            if b_val < a_val:
                at_least_one_better = True
    return at_least_one_better
```

### Складність

O(N²) — для кожної альтернативи перевіряємо домінування іншими. Для 5 моделей — миттєво.

### У застосунку

`/benchmark/selection?domain=...` — на сторінці є секція «Парето-множина» з плашками моделей. Натискання на плашку дає підсвічування — наочно бачиш які моделі залишаються.

## 7. Поширені плутанини

### Чому Парето не дає одну відповідь

«Я зробив Парето-аналіз — і отримав 3 моделі. Яка краща?»

**Відповідь:** Парето **не дає** одну. Він **відсіює гірші**. Щоб обрати з 3 — потрібен **інший** метод (MCDA з вагами).

### Чи може Парето бути порожнім

**Ні**. У зкінченій множині завжди є **хоча б одна** недомінована альтернатива (та, що максимізує одну з осей).

### Чи може Парето містити всі альтернативи

**Так, в крайньому випадку**. Якщо кожна альтернатива лідер за одним критерієм — нікого не можна викинути. У реальності рідко.

### Парето-фронт vs Парето-множина

В літературі іноді розрізняють:
- **Парето-множина (Pareto set):** множина альтернатив у просторі **рішень** (тут — моделей)
- **Парето-фронт (Pareto front):** їхні значення у просторі **критеріїв**

На практиці слова часто взаємозамінні. У твоїй роботі — «Парето-множина» в обох сенсах.

### Чи врахувано equality

Якщо `a_j == b_j` для всіх j — альтернативи **однакові**. Жодна не домінує. Обидві в Парето.

Якщо `a_j == b_j` для всіх, крім одного — там `a > b` — `a ≻ b` (a домінує b).

У твоїй роботі ця ситуація обходиться правильно (умова `at_least_one_better` у коді).

## 8. Multi-objective optimization

Парето — частина широкого поля **multi-objective optimization (MOO)**.

### Класичні MOO задачі

- Дизайн літака: aerodynamics vs weight vs cost
- Управління портфелем: return vs risk
- Будівельний дизайн: cost vs sustainability vs comfort

### Методи MOO

- **Парето-методи:** генерують Парето-фронт; вибір залишається користувачу
- **Скалярні методи:** перетворюють кілька критеріїв в один (через ваги — як твоя MCDA)
- **Eвристичні:** NSGA-II, MOEA/D — генетичні алгоритми

### Чому в IR використовують Парето

Бо це **робастний перший крок**. Не вимагає apriori знання ваг. Залишає простір для **інтерактивного вибору** користувачем.

### У ML/IR

Стало популярно через benchmarks типу MTEB і BEIR — там моделі порівнюються за багатьма метриками. Парето-аналіз стандартизує «який варіант розумно вибрати».

## 9. Перевірочні питання з відповідями

### Q1. Чи може Парето-множина містити **всі** альтернативи? Коли таке буває?

**A:** Так, теоретично. Якщо **кожна** альтернатива лідер хоча б за одним критерієм, нікого не можна виключити. У реальності рідко — зазвичай кілька моделей домінуються.

### Q2. На юридичному домені у Парето-множину входить Qwen3 чи ні?

**A:** **Так**, входить. На legal: Парето-множина = {BGE-M3, Qwen3, E5-base, BM25}. Qwen3 — лідер за nDCG (0.3199), хоч і повільніший. Його ніхто не домінує: BGE кращий за швидкодією, але гірший за nDCG → trade-off.

(Перевірити можна у застосунку: `/benchmark/selection?domain=legal`.)

### Q3. Чому Парето-аналіз — це лише **перший** крок MCDA, а не вся MCDA?

**A:** Бо Парето залишає **множину** альтернатив. Щоб обрати **одну** — треба врахувати **пріоритети користувача** (через ваги критеріїв). MCDA з лінійною згорткою це робить: розраховує інтегральну оцінку U для кожної Парето-альтернативи і обирає максимальну.

### Q4. Що буде, якщо я зміню напрям одного критерію — наприклад, латентність на максимізацію?

**A:** Парето-множина може **повністю змінитися**. Якщо «латентність маx» (хочеш повільні моделі — недоречно, але технічно), то Qwen3 (463 мс) виграє, BM25 (0.4 мс) — програє. Парето кардинально зміниться. **Напрямок критерію — критично важливий**.

### Q5. Що, якщо дві моделі мають **однакові** значення за всіма критеріями?

**A:** Обидві в Парето (бо жодна не домінує іншу — нема «хоча б одного кращого»). Це **дублікати в Парето-множині**. У моїй роботі такої ситуації нема, але теоретично можлива.

### Q6. Як виглядає Парето-фронт, якщо у нас 5 критеріїв (як у тебе)?

**A:** Геометрично — у 5-вимірному просторі, неможливо візуалізувати. Тому показую **проєкції на 2D** (nDCG vs latency на слайді 16). Альтернатива — паралельні координати, але важко читати.

### Q7. Якщо Парето-множина — 5 моделей з 5 (нікого не виключено) — що це значить?

**A:** Усі моделі мають **унікальні переваги**. Жодна не домінує жодну. Це **слабке** обмеження для вибору — MCDA доведеться розглянути всі 5. У моїй роботі такого не сталося — є явно гірші моделі (Qwen3 на tech, nomic скрізь).

### Q8. Чи можна Парето обчислити для 2-х моделей?

**A:** Так, тривіально. Обидві в Парето, окрім випадку, коли одна домінує іншу (тоді вона одна в Парето). Сенс — нема: Парето корисний при ≥3 моделях.

### Q9. Що означає, що BM25 — Парето-оптимальна, але має найгірший nDCG?

**A:** Це здається парадоксально, але:
- BM25 **найшвидша** (0.4 мс)
- За швидкодією — лідер
- Жодна інша модель **не швидша**
- → BM25 не домінується нікого
- → у Парето

Якщо обмежити дослідження тільки nDCG — BM25 була б віддалена. Але **зі швидкодією як критерієм** — вона залишається раціональним вибором (для real-time сценаріїв).

### Q10. Як аргументувати на захисті, чому Парето — потрібний крок?

**A:** Бо це **робастний інструмент відсіву явно гірших опцій без апріорних ваг**. Перевірка домінування — простий, прозорий, інтуїтивний крок. Користувач бачить «ось 3 моделі, які варто розглянути; інші — заздалегідь гірші». Подальша згортка (MCDA) працює лише з цими 3, що зменшує обчислення і робить вибір інтерпретовним.
